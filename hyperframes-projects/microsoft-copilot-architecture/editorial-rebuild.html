Microsoft 365 Copilot

How Microsoft Copilot works

You ask Copilot in Word to summarize a project. The request looks simple, but the useful answer depends on more than a language model. It needs the right work context, and it needs to respect your access.

First, Copilot preprocesses your prompt. It uses grounding to connect the request with relevant context, such as files, emails, chats, meetings, and other Microsoft 365 content available through Microsoft Graph.

That grounded prompt goes to a large language model. The model generates a response for the task, and Copilot returns it to the app, with the work context making the result more relevant and actionable.

But grounding does not mean tenant-wide access. Copilot can only surface organizational data the signed-in user is already allowed to view. Documents outside that permission boundary stay outside the response.

The same Microsoft 365 boundary continues to protect the interaction. Customer data remains within the service boundary, data is encrypted in transit, and prompts, responses, and Graph-accessed data are not used to train foundation language models.

Finally, Copilot honors the controls your organization already uses, including Conditional Access and multifactor authentication. So the architecture is not a model with unlimited visibility. It is an orchestrated flow: prompt, permitted context, model, protected response.
