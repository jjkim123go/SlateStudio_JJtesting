## Line 1

Need to update a published article but don’t have an issue yet? Start in Content Studio to create one and get a draft going.

## Line 2

Select Update to create a new issue for the article that needs to change.

## Line 3

Provide the context the agent needs. Include the article, the reason for the change, and any details that explain what should be updated. That might be a roadmap-driven feature change, customer feedback, a correction, or another update request.

## Line 4

Content Studio creates the issue and uses the context you provided to draft an update to the existing article. This will take several minutes for the agent to complete. The proposed change comes back as a linked pull request, or PR, for review.

## Line 5

The agent’s draft is a starting point, not the final version. Review the changes for technical accuracy, completeness, links, screenshots, metadata, and customer readiness before you sign off.

## Line 6

Edit the draft if needed. In the PR, select Open in Content Mentor to open in VS Code on the web. If it’s your first time using Content Mentor, you may be prompted to complete a few additional setup steps.

## Line 7

Content Mentor creates a fork, pulls in the Content Studio branch, and opens the draft for editing. Make your changes, then select Create PR.

## Line 8

Update M S dot date only if you’ve completed a full accuracy review of the article; otherwise, select Skip. Then select Create Pull Request. Content Studio merges your edits back into the original PR.

## Line 9

When the update is accurate and ready for customers, merge the PR to publish it. After the review is complete and the change is processed, the related Content Studio accuracy issue may close automatically.

## Line 10

That’s it. Use Update in Content Studio to create an issue and get a proposed draft, then review the linked PR and merge it when the update is ready to publish. You stay in control of the final content while spending less time on the first draft.
